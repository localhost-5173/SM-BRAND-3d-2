# SM BRAND — Project Overview

**Document Version:** 1.0.0  
**Project:** SM BRAND Industrial Strapping & Packaging Systems  
**Target Market:** Industrial manufacturing, logistics, and export packing facilities across Pakistan (Karachi, Lahore, Faisalabad, and nationwide)  

---

## 1. Goal

The goal of this project is to evolve the existing high-performance static B2B website into a dynamic, manageable packaging machinery catalog powered by a Node.js + Express backend and MongoDB Atlas database, paired with a co-located, lightweight administrative dashboard.

The solution allows the business owner to:
1. Dynamically manage the machinery and consumables catalog (CRUD operations, status toggling, Cloudinary image uploads).
2. Centrally configure public contact coordinates, phone numbers, and WhatsApp routing from a single administrative dashboard without touching source code.
3. Track and organize quotation leads generated by the public website.
4. Manage the spare parts catalog and machine comparison matrix dynamically.
5. Preserve 100% of the existing frontend design, animations, and 3D experience without unnecessary code rewrites.

---

## 2. Public Website Pages

The public-facing frontend consists of 7 standalone HTML pages sharing a single monolithic design stylesheet (`assets/css/sm.css`) and modular JavaScript scripts:

| Page | File | Core Features & Responsibilities |
|---|---|---|
| **Homepage** | `index.html` | High-impact industrial landing page. Features a procedural Three.js 3D model of the SM-801 Auto Arch strapper, GSAP-driven marquee velocity ticker, animated operational metric counters, bento editorial showcase, dynamic ready stock card grid, 3-step operational timeline, interactive machinery recommendation wizard, verified plant manager reviews, and quotation CTA banner. |
| **Machinery** | `machines.html` | Dedicated catalog for strapping machines. Features category filter tabs (`All Models`, `Semi-Automatic`, `Automatic Arch`, `High-Speed Inline`), dynamic product card rendering, and a technical comparison matrix. |
| **Rolls & Consumables** | `rolls.html` | Catalog for strapping media and hardware accessories. Includes filter tabs for PP strapping, PET export strapping, and seals/buckles, plus an 11-color industrial swatch showcase and bulk discount inquiry triggers. |
| **Battery & Hand Tools** | `tools.html` | Mobile packaging equipment showcase featuring dual asynchronous card grids: Cordless Battery Tools (friction-weld) and Manual Hand Tools (tensioners, sealers, carts, blades). |
| **Service & Spares** | `service.html` | Field engineering capabilities overview (commissioning, 24h breakdown response, spare parts inventory), WhatsApp video breakdown helpline trigger, and common replacement parts pricing table. |
| **Contact & Quotation** | `contact.html` | Direct quotation builder with field validation (Name, WhatsApp, City, Equipment Need, Note), dual dispatch (WhatsApp prefilled chat + backend lead capture), depot coordinates (Karachi, Lahore, Faisalabad), and business hours. |
| **Product Detail** | `product.html` | Dynamic detail view hydrating product metadata from URL query parameters (`?slug=...` or `?id=...`). Displays high-resolution image plate, status indicator, warranty checklist, technical specifications list, instant quotation action, and 3 complementary related product cards. |

## 3. Project Scope

### 3.1. What Is In Scope

```
[In-Scope Deliverables]
├── Frontend Stabilization:
│   ├── Eliminate 280ms artificial page transition delay caused by inactive curtain handler
│   ├── Remove CPU/GPU cycle waste from inactive cursor spotlight loop
│   ├── Fix unrendered Lucide arrow icon in product.html 404 state
│   ├── Reconcile and rename obsolete --orange CSS token to --accent
│   └── Update README.md to accurately document the approved monochrome dark design system
├── Backend API (Node.js + Express):
│   ├── RESTful public endpoints: /api/products, /api/products/:slug, /api/spares, /api/settings, /api/leads
│   ├── RESTful admin endpoints: authentication, product CRUD, spare parts CRUD, settings update, media upload, lead management
│   ├── MongoDB Atlas connection via Mongoose with strict schema validation
│   └── Robust error handling with uniform JSON error envelopes
├── Admin Dashboard:
│   ├── Lightweight single-page application served directly by Express at `/admin` on the SAME origin
│   ├── Product manager with Cloudinary direct drag-and-drop image upload
│   ├── Spare parts inventory manager
│   ├── Central settings manager (WhatsApp numbers, phone, email, depot addresses, business hours)
│   └── Lead pipeline manager with direct WhatsApp 1-click reply integration
└── Frontend Dynamic Integration:
    ├── Update assets/js/sm-config.js to communicate with the Express API
    ├── Hydrate WhatsApp number and depot details dynamically from /api/settings
    └── Graceful offline fallback to assets/js/sm-data.js if the backend is unreachable
```

### 3.2. What Is Out of Scope

- **No Public Redesign or Framework Rewrite:** The public website remains vanilla HTML5, CSS3, and JavaScript. It will NOT be converted to React, Next.js, Vue, or any other framework.
- **No E-Commerce Cart or Checkout:** SM BRAND operates strictly as a B2B high-ticket equipment distributor. Products do not feature "Add to Cart" or online credit card checkout; transactions are quotation-based and finalized via direct WhatsApp and enterprise purchase orders.
- **No Payment Gateway Integration:** Stripe, PayPal, JazzCash, or EasyPaisa checkout flows are not in scope.
- **No Complex Multi-Tenant RBAC:** The admin system uses a single administrative role (`admin`). Multi-tier user permissions, customer accounts, and vendor portals are out of scope.
- **No Database Modification of 3D Canvas:** The Three.js 3D hero model remains procedurally generated on the client; it is not loaded from dynamic CAD/GLTF files from the database.
